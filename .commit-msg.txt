fix(models): drop fabricated MiniMax-M3 pricing from seeded catalog

minimax is a custom Anthropic-compatible endpoint that is excluded from
Models::DetectCatalogDrift, so the RubyLLM registry never backfills this
KNOWN_MODELS row (unlike the native anthropic/openai/google entries). The
guessed input/output cost values therefore persisted verbatim into cost
tracking/billing. Leave pricing nil until confirmed against MiniMax's
published pricing, and document that the row exists for catalog
completeness (so direct-outbound minimax runners pass validation) rather
than to fix the runtime model_not_found — opencode registers the model via
Runner#opencode_custom_provider_models and provider-qualifies the resolved
tier model via Runner#qualified_model_for.

Addresses review threads on #2667.
