# Dependency Declaration EARS

> Parent: [Dependency Declarations](dependency-declarations-design.md)
>
> The IDs below are stable grep targets for implementation and tests.

- [x] **DEPENDENCY-DECLARATIONS-001** — When a dependency section contains a bare local or qualified issue reference in a Markdown bullet, ordered, or checklist list item that is not an indented code block, the system SHALL extract it as a dependency.
- [x] **DEPENDENCY-DECLARATIONS-002** — When ordinary prose beneath a dependency heading mentions issue references without an explicit directive or list-item declaration, the system SHALL not extract those references as dependencies.
- [x] **DEPENDENCY-DECLARATIONS-003** — When explicit positive, negative, removal, or deployment directives occur in supported locations, the system SHALL retain their existing qualified-reference, deployment-flag, and ordered-comment behavior, subject to the contextual exclusions in DEPENDENCY-DECLARATIONS-009.
- [x] **DEPENDENCY-DECLARATIONS-004** — When a child section or child-issue list is outside the dependency section, the system SHALL exclude its inline dependency phrases; a later Markdown heading SHALL end bare-reference admission for the preceding dependency section.
- [x] **DEPENDENCY-DECLARATIONS-005** — When Auto-Pick persists an edge or Auto-Merge evaluates a live pull request body and comments, both consumers SHALL use the same extraction contract and Auto-Merge SHALL remain unresolved when declared remote evidence cannot be verified.
- [x] **DEPENDENCY-DECLARATIONS-006** — When a dependency-section list item spans continuation lines indented to at least the list item's content position, measured in CommonMark columns with tabs advancing to four-column stops, the system SHALL extract bare references from the folded item text including those continuation lines; lesser indentation SHALL end the item.
- [x] **DEPENDENCY-DECLARATIONS-007** — When dependency-section content appears inside a fenced code block, the system SHALL not admit it as a list-item declaration, because fenced content is code rather than Markdown list structure; only a fence with the opening delimiter character and at least its opening length SHALL close that block.
- [x] **DEPENDENCY-DECLARATIONS-008** — When any write would add or resolve a local blocking dependency edge, the system SHALL reject the write if the resulting account-scoped blocking graph contains a cycle, report the exact dependent-to-prerequisite cycle path, and preserve the child-to-parent contextual-reference exception.
- [x] **DEPENDENCY-DECLARATIONS-009** — When an issue body or comment quotes a dependency directive in Markdown code or describes a numbered issue other than the current item as having or lacking a dependency on another issue, including an immediately comma-attributed supported directive (`#N, blocked by #M` or `#N, is blocked by #M`) in prose or a dependency-section list item and its valid folded continuation lines, the parser SHALL NOT turn that issue or its prerequisites into prerequisites of the current item. The comma attribution SHALL apply only when the numbered subject immediately precedes the comma; an unrelated earlier reference SHALL NOT suppress a current-item directive. An actual directive or bare dependency-section list-item declaration for the current item in the same text SHALL still be extracted.
- [x] **DEPENDENCY-DECLARATIONS-010** — When Auto-Merge evaluates a declared qualified cross-project prerequisite, it SHALL resolve it only through the exact case-normalized project tracked in the same account and that project's configured provider identity. It SHALL accept a currently closed issue or merged pull request and SHALL keep open issues, closed-unmerged pull requests, missing or inaccessible tracked sources, untracked sources, and provider failures blocked; local Paid state, completed runs, and inferred project relationships SHALL NOT satisfy the declaration.
