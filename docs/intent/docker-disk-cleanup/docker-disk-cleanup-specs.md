# Docker Disk Cleanup Specifications

- [x] **DOCKER-DISK-CLEANUP-001** — When daily Docker disk cleanup is scheduled, Paid SHALL use the GoodJob maintenance queue at 04:17 UTC with at most one executing job and one queued copy and a twenty-minute execution timeout, and SHALL perform cleanup only when explicitly enabled and connected through a local Unix socket.
- [x] **DOCKER-DISK-CLEANUP-002** — When Docker disk cleanup selects images, Paid SHALL delete only images created more than seven days ago that have no running or stopped container references, SHALL preserve Paid agent images and all aliases of configured runtime images including unselected configuration and environment catalog identities, and SHALL use non-forced deletion with implicit parent pruning disabled.
- [x] **DOCKER-DISK-CLEANUP-003** — When Docker disk cleanup prunes build cache, Paid SHALL request only unused cache older than seven days with a fifteen-minute read timeout, and SHALL never delete containers, networks, or volumes.
- [x] **DOCKER-DISK-CLEANUP-004** — When Docker disk cleanup completes, Paid SHALL log removed-image count, estimated image bytes, cache bytes reclaimed, and duration, and SHALL log image-phase results before pruning cache so partial progress remains visible on failure; if configuration or Docker discovery fails, Paid SHALL surface the failure without proceeding to subsequent deletions, while tolerating missing-image and deletion-conflict races.
