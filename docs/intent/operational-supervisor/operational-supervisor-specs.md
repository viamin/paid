# EARS Specs: Operational supervisor

- [ ] **OPERATIONAL-SUPERVISOR-001** — When the operational supervisor builds an account snapshot, the system SHALL include only versioned allowed numeric aggregates, enum categories, ages, and Paid-local numeric identifiers, and SHALL represent an unavailable measure without substituting zero.
- [ ] **OPERATIONAL-SUPERVISOR-002** — When an account snapshot is prepared for analysis, the system SHALL exclude user and repository content, issue/PR text, comments, diffs, paths, prompts, agent output/logs/summaries, credentials, secrets, raw provider responses, and raw exception text.
- [ ] **OPERATIONAL-SUPERVISOR-003** — When the enabled supervisor analyzes a valid snapshot, the system SHALL call `agent_harness` with a versioned policy prompt, action catalog, and JSON-schema response contract; no application path SHALL call a provider directly for supervisor analysis.
- [ ] **OPERATIONAL-SUPERVISOR-004** — If supervisor output is malformed, contains an unknown value or target, is stale, duplicates an open incident, or fails current policy preconditions, then the system SHALL create no mitigation and SHALL record a sanitized health or validation outcome.
- [ ] **OPERATIONAL-SUPERVISOR-005** — When a valid finding is first observed, the system SHALL persist one account-scoped incident with a stable fingerprint, sanitized evidence, analysis/prompt versions, lifecycle timestamps, and scoped targets; open critical and warning incidents SHALL be visible above dashboard metrics to authorized operators.
- [ ] **OPERATIONAL-SUPERVISOR-006** — Where `operational_supervisor_enabled`, account policy, and project opt-in are all current, the system SHALL apply only `pause_pr_followups` or `pause_project_autopick` after locking and rechecking the target, and SHALL make each action idempotent, audit-recorded, and narrower than a project-wide user pause.
- [ ] **OPERATIONAL-SUPERVISOR-007** — When a supervisor-owned mitigation expires or an authorized operator resolves it, the system SHALL reverse only that mitigation overlay, retain the incident/action evidence, and SHALL NOT infer semantic or quality progress as an automatic recovery condition.
- [ ] **OPERATIONAL-SUPERVISOR-008** — While the supervisor account flag is disabled, the system SHALL make no supervisor LLM call and SHALL create no mitigation; disabling the flag during rollout rollback SHALL prevent new actions and permit reversal only of supervisor-owned overlays.
