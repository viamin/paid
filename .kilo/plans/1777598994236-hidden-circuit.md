# Plan: Regenerate Local Databases with Data Preservation

## Goal
Eliminate local schema drift on `paid_development` and `paid_development_cable` by dropping/recreating them from migrations, while preserving all existing data.

## Current State
- **paid_development**: 87 tables, 237 applied migrations, 233 migration files on disk. Significant data: 161K knowledge_artifacts, 32K agent_run_logs, 10K agent_runs, 2.6K collector_runs, 1.9K issues, 12 projects, etc.
- **paid_development_cable**: 3 tables, 24K rows in solid_cable_messages (ephemeral)
- **Extensions**: `pg_trgm`; **Custom functions**: `paid_current_account_id()`, `paid_tenant_bypass()`; **Trigger**: `knowledge_chunks_tsvector_update`
- **RLS**: Extensive tenant isolation policies on ~50+ tables
- No partitioned tables, no custom enums, no views, no custom schemas

## Decisions
- **Cable DB**: Start empty — Solid Cable messages are transient
- **RLS handling**: Temporarily disable RLS via `ALTER TABLE ... DISABLE ROW LEVEL SECURITY / NO FORCE ROW LEVEL SECURITY` (verified that `paid` user can do this on its own tables). Re-enable by re-running `bin/rails db:migrate` which is idempotent.

## Phase 1: Create `bin/pg-dump` Backup Script

Create executable bash script at `bin/pg-dump`:
- Uses `pg_dump --format=custom` (compressed, supports `pg_restore`)
- Dumps both `paid_development` and `paid_development_cable`
- Saves to `tmp/pg_dumps/` with ISO-8601 timestamps
- Reads connection from env vars (`DB_HOST`, `DB_USERNAME`, `DB_PASSWORD`) with defaults (`postgres`, `paid`, `paid`)
- Prints paths and sizes on success; exits non-zero on failure

### 2.4: Capture pre-drop row counts

```bash
PGPASSWORD=paid psql -h postgres -U paid -d paid_development -t -A -c \

```

### 2.5: Create practice DB + run migrations from scratch
```bash
createdb -h postgres -U paid paid_practice 2>/dev/null || true
PGPASSWORD=paid psql -h postgres -U paid -d postgres -c "DROP DATABASE IF EXISTS paid_practice;"
PGPASSWORD=paid psql -h postgres -U paid -d postgres -c "CREATE DATABASE paid_practice OWNER paid;"

RAILS_ENV=development DATABASE_URL="postgres://paid:paid@postgres/paid_practice" \
  bin/rails db:migrate
```
This validates that all 233 migrations run cleanly from scratch.

### 2.6: Disable RLS on practice DB, restore data, re-enable RLS
```bash
# Disable RLS + FORCE on all public tables
PGPASSWORD=paid psql -h postgres -U paid -d paid_practice -t -A -c "
  SELECT 'ALTER TABLE ' || schemaname || '.' || tablename ||
         ' DISABLE ROW LEVEL SECURITY;' ||
         'ALTER TABLE ' || schemaname || '.' || tablename ||
         ' NO FORCE ROW LEVEL SECURITY;'
  FROM pg_tables WHERE schemaname = 'public';" | \
  PGPASSWORD=paid psql -h postgres -U paid -d paid_practice

# Data-only restore
pg_restore --data-only --no-owner --disable-triggers \
  --host=postgres --username=paid \
  --dbname=paid_practice tmp/pg_dumps/paid_development_*.dump

# Re-enable RLS by re-running migrations (idempotent)
RAILS_ENV=development DATABASE_URL="postgres://paid:paid@postgres/paid_practice" \
  bin/rails db:migrate
```

### 2.7: Verify practice restore

## Key Technical Notes

1. **RLS bypass verified**: `ALTER TABLE ... DISABLE ROW LEVEL SECURITY` works as `paid` user (table owner). No superuser needed.
2. **Sequence reset**: `reset_pk_sequence!` handles all standard serial/identity PKs. Tables without serial PKs are skipped via rescue.
3. **Re-running `db:migrate` to re-enable RLS**: All RLS-related migrations use idempotent patterns (e.g., `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` is a no-op if already enabled). Verified this is safe.
4. **`pg_restore --disable-triggers`**: Disables trigger firing during restore, which prevents the `knowledge_chunks_tsvector_update` trigger from running on every insert (significant performance improvement for 2.3K rows). The tsvector column will be populated from the dump data directly.
5. **Backup format**: Custom format (`-Fc`) is compressed (~530KB for primary DB) and supports `pg_restore --list` for verification and `--data-only` for selective restore.

## Failure Recovery
If anything goes wrong during Phase 3, the full backups from Step 3.1 can restore the original state:
```bash
# Nuclear option: restore from backup completely
PGPASSWORD=paid psql -h postgres -U paid -d postgres -c "DROP DATABASE paid_development;"
PGPASSWORD=paid psql -h postgres -U paid -d postgres -c "CREATE DATABASE paid_development OWNER paid;"
pg_restore --no-owner --host=postgres --username=paid \
  --dbname=paid_development tmp/pg_dumps/paid_development_*.dump
```
